# Transport (TS)

The TypeScript implementation of the `elsewise.transport.v1` envelope: `Channel` multiplexes any number of concurrent
calls over one `Wire`, `WebSocketWire` and `DataChannelWire` are that wire over a WebSocket and a WebRTC data channel,
and `createClient`/`serve` put a typed rpc surface over it using `@bufbuild/protobuf` service descriptors. Sibling folders
under `transport/` will hold the other languages' implementations of the same protocol.

Run pnpm from the **repo root**: `pnpm --filter @elsewise/transport <script>`.

## Layout

| Path          | What it is                                                                                   |
|---------------|----------------------------------------------------------------------------------------------|
| `src/`        | The library. `index.ts` is the public surface; consumers import `@elsewise/transport`.       |
| `src/wire/`   | The `Wire` interface (`index.ts`) and the wires over it: `socket.ts` is what the socket wires share, `websocket.ts` and `data-channel.ts` each one of them. |
| `src/gen/`    | protobuf-es bindings for the envelope. Gitignored, regenerated by `pnpm generate`.           |
| `test/`       | Vitest suites (plain Node). `test/wire/` mirrors `src/wire/`: the `memory` harness (with a `capacity` to hold the pipe full and `drain()` it by hand), the `fake-socket` fakes, `websocket`'s suite over a `ws` server and `data-channel`'s over a fake. |
| `test/proto/` | `TestService` — the service the suites call through the typed client and server. Test-only.  |
| `test/gen/`   | protobuf-es bindings for `test/proto/`. Gitignored, regenerated by `pnpm generate`.          |

This is a **source package**: `exports` points straight at `src/index.ts` and there is no build step — workspace
consumers (Vite, vitest) compile it themselves.

## The socket wires

`SocketWire` is the abstract base holding what a WebSocket and an RTCDataChannel share — the `Socket` interface:
`binaryType`, `bufferedAmount`, `send`, `close` and `addEventListener` for `message` and `close` — so the package
names neither (it has no DOM types). It frames binary messages, rejects text ones by closing the socket with code
1000 (the spec allows a client no other) and reason `binary messages only`, fires `onClosed` once however the wire
ends (a local `close` included, so a caller who kept the wire cannot strand the channel), and owns the high-water
mark. A `Wire` sends `Uint8Array<ArrayBuffer>` frames, which is what `toBinary` produces and what a socket's `send`
accepts. Each subclass adds what only its socket needs: `WebSocketWire` the heartbeat probe and a drain poll,
`DataChannelWire` the `bufferedamountlow` hook and no probe at all. The split exists so neither has a default the
other must remember to turn off. The constructor takes an **open** socket; `WebSocketWire.open(socket)` or
`DataChannelWire.open(channel)` resolves to a wire once one opens and rejects if it closes first. Constructing the
socket, the auth token as subprotocol, timeouts and reconnects belong to the connection layer above. The WebSocket
suite (`test/wire/websocket.test.ts`) runs the runtime's `WebSocket` against a `ws` server over loopback, so both
implementations are covered; the data channel suite runs over a fake, as Node has no RTCDataChannel.

## Sending

A stream's frames never go straight to the wire. Each stream queues them in its own outbound and the channel sends one
frame from each pending queue in turn, so a stream with a 16 MiB message in flight cannot starve the others: a frame
waits behind at most one frame of every other active stream, never behind a whole message. The channel only sends
while the wire is `writable` and resumes on its `onDrain`, which keeps the socket's own buffer short enough that this
ordering actually reaches the network rather than piling up behind bytes already handed to the socket. A socket wire
reports full once `bufferedAmount` reaches `highWaterMark` (`DEFAULT_HIGH_WATER_MARK`, 256 KiB) and drains at half of
it: `DataChannelWire` sets that as the channel's `bufferedAmountLowThreshold` and forwards its `bufferedamountlow`,
`WebSocketWire` has no such event and polls every few ms while full. Raise the mark on a fast link if throughput
matters more than how long a small call waits.

`send` on either stream resolves once the message's last fragment has been handed to the wire, or at once if the call
is already finished. That is the backpressure: `serve`'s streaming relays and the client's client-streaming call await
it, so an impl's or caller's iterable is pulled no faster than the wire takes it. Not awaiting it queues without bound.
A cancel drops the stream's queued fragments and sends only the Cancel (nothing at all if its Open never left), a
requester whose End has arrived drops its queue, and a responder whose requester cancelled drops its queued responses
and sends only the End.

## Heartbeat

Liveness is the wire's concern, not the channel's: the channel only multiplexes streams and learns of a dead
connection through `onClosed` like any other close. The heartbeat has two halves. Answering is protocol: every
socket wire answers a `HeartbeatEnvelope` carrying `Ping` with one carrying `Pong` and passes neither up, since any
peer in any language may probe over any wire. Probing is policy: only `WebSocketWire` sends `Ping` every `heartbeat`
ms (`DEFAULT_HEARTBEAT_MS`, 15 s) and, if nothing at all arrives between two consecutive probes, closes with reason
`heartbeat timeout`, so a peer that vanished without closing the socket (network drop, sleep, NAT expiry) is noticed
within two intervals rather than never. The heartbeat envelope is defined in the proto so every language agrees on
its bytes, but it is always sent bare, so the wire matches the two frames byte for byte instead of decoding. The
timer is unref'd so it never keeps a Node process alive. A WebSocket always needs the probe (browsers cannot send
protocol pings), so it cannot be turned off; `DataChannelWire` never probes and relies on ICE, since a probe would
give up on a pause an ICE restart could recover from, and the connection layer closes it when the peer connection
reports `failed`. Every peer implementation's wires must answer `Ping`.

## Limits

Backpressure is sender-side only (see Sending): the receive queues are unbounded, so a fast peer can grow memory on a
slow consumer until there is a credit window in the protocol. A reassembled message is capped at 16 MiB
(`MAX_MESSAGE_BYTES`) — an oversized request is ended with `CODE_RESOURCE_EXHAUSTED`, an oversized response is
cancelled and fails with it. The channel itself survives. `transport/rust/` enforces the same cap.

## Imports

No aliases here — the package is one small tree, so every import is relative, including tests reaching `../src`.

## Generated code

Never hand-edit; Biome excludes both `gen/` folders. Two buf templates feed them: `buf.gen.yaml` generates the
envelope from `../../../proto` (only `elsewise/transport`), and `buf.gen.test.yaml` generates `TestService` from
`test/proto/`. `prepare` regenerates on install.

The split is deliberate. The envelope bindings are **live**: a change to `proto/elsewise/transport/` is supposed to
break these suites — that is the signal the implementation and contract drifted. `TestService` is owned by the tests
and free to change; it exists so the suites do not couple to the daemon's rpcs, which churn for reasons that have
nothing to do with the transport.
