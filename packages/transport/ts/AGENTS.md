# Transport (TS)

The TypeScript implementation of the `elsewise.transport.v1` envelope: `Channel` multiplexes any number of concurrent
calls over one `Wire` (a WebSocket or WebRTC data channel), `SocketWire` is that wire over either, and
`createClient`/`serve` put a typed rpc surface over it using `@bufbuild/protobuf` service descriptors. Sibling folders
under `transport/` will hold the other languages' implementations of the same protocol.

Run pnpm from the **repo root**: `pnpm --filter @elsewise/transport <script>`.

## Layout

| Path          | What it is                                                                                   |
|---------------|----------------------------------------------------------------------------------------------|
| `src/`        | The library. `index.ts` is the public surface; consumers import `@elsewise/transport`.       |
| `src/wire/`   | The `Wire` interface (`index.ts`) and the wires over it: `socket.ts` for WebSocket and RTCDataChannel. |
| `src/gen/`    | protobuf-es bindings for the envelope. Gitignored, regenerated by `pnpm generate`.           |
| `test/`       | Vitest suites (plain Node). `test/wire/` mirrors `src/wire/`: the `memory` harness and `socket`'s suite over a `ws` server. |
| `test/proto/` | `TestService` — the service the suites call through the typed client and server. Test-only.  |
| `test/gen/`   | protobuf-es bindings for `test/proto/`. Gitignored, regenerated by `pnpm generate`.          |

This is a **source package**: `exports` points straight at `src/index.ts` and there is no build step — workspace
consumers (Vite, vitest) compile it themselves.

## The socket wire

`SocketWire` adapts what a WebSocket and an RTCDataChannel share — the `Socket` interface: `binaryType`, `send`, `close`
and `addEventListener` for `message` and `close` — so one class serves both, and the package names neither (it has no
DOM types). The constructor takes an **open** socket; `SocketWire.open(socket)` resolves to a wire once one opens and
rejects if it closes first. Constructing the socket, the auth token as subprotocol, timeouts and reconnects belong to
the connection layer above. Binary messages are frames; a text message closes the socket with code 1000 (the spec allows
a client no other) and reason `binary messages only`, as the envelope is never text. A `Wire` sends
`Uint8Array<ArrayBuffer>` frames, which is what `toBinary` produces and what a socket's `send` accepts. `onClosed` fires
once however the wire ends, a local `close` included, so a caller who kept the wire cannot strand the channel. Its suite
(`test/wire/socket.test.ts`) runs the runtime's `WebSocket` against a `ws` server over loopback, so both implementations
are covered.

## Limits

No backpressure: every queue is unbounded. A reassembled message is capped at 16 MiB (`MAX_MESSAGE_BYTES`) — an
oversized request is ended with `CODE_RESOURCE_EXHAUSTED`, an oversized response is cancelled and fails with it. The
channel itself survives. `transport/rust/` enforces the same cap.

## Imports

No aliases here — the package is one small tree, so every import is relative, including tests reaching `../src`.

## Generated code

Never hand-edit; Biome excludes both `gen/` folders. Two buf templates feed them: `buf.gen.yaml` generates the
envelope from `../../../proto` (only `elsewise/transport`), and `buf.gen.test.yaml` generates `TestService` from
`test/proto/`. `prepare` regenerates on install.

The split is deliberate. The envelope bindings are **live**: a change to `proto/elsewise/transport/` is supposed to
break these suites — that is the signal the implementation and contract drifted. `TestService` is owned by the tests
and free to change; it exists so the suites do not couple to the daemon's rpcs, which churn for reasons that have
nothing to do with the transport.
