# Components

shadcn components over Base UI, React 19, Tailwind v4 — the implementation of `DESIGN.md` at the repo root.

Run pnpm from the **repo root**: `pnpm --filter @elsewise/components <script>`.

## Layout

| Path               | What it is                                                                    |
|--------------------|-------------------------------------------------------------------------------|
| `src/components/`  | One component per file, flat. `file-tree/` is the one directory, entered via  |
|                    | `file-tree.tsx` beside it.                                                    |
| `src/lib/`         | Helpers. `utils.ts` is `cn()`.                                                |
| `src/styles.css`   | The Tailwind entry and structure: token mapping, type scale, radius.          |
| `src/elsewise.css` | The default theme's values, and nothing else.                                 |
| `test/`            | Shared harness.                                                               |
| `test/visual/`     | Screenshot sheets and their `__screenshots__/` baselines.                     |

- A **source package**: `exports` points at `src/` and there is no build step. `exports` lists each public module by
  name; a file it does not list cannot be imported from outside.
- `src/lib/file-icons.gen.ts` and `src/assets/file-icons/` are generated by `tools/` and committed. Never hand-edit;
  see `tools/AGENTS.md`.

## Rules

- **Components stay pure.** A component takes what it needs as props. It never reads settings, the bridge or
  `window.platform` — the app owns that wiring.
- **Relative imports only**: `./button`, `../lib/utils`. No `@/` alias and no importing the package by name.
- **React by name**: `import { type ComponentProps, useState } from 'react'`, never the `React.` namespace.
- **Comments**: `//` for comments, `/** … */` for doc comments, `/* … */` only inside an expression or in CSS. Wrap
  prose at 120 columns by hand. Keep comments in test files to a minimum.

## Icons

- Never import `@phosphor-icons/react`; draw `<Icon name="check" />` from `./icon`. Biome enforces this outside
  `icon.tsx` and `test/`.
- `icon.tsx` maps each **role** to a Phosphor icon. Name a role for what it does, not what it looks like, and add one
  to `DEFAULT_ICONS` when none fits.
- `<FileIcon name="main.ts" />` resolves against the generated tables.
- The app overrides either set through `IconProvider` and `FileIconProvider`; `useIcons()` and `useFileIcons()` return
  the merged maps.
- The file tree's rows live in a shadow root and cannot render components, so `file-tree/icons.ts` builds a sprite and
  `data:` URIs instead. Its letterform tile mirrors `file-icon.tsx`; change both.

## Styling

`styles.css` is the one stylesheet a consumer imports, **instead of** `tailwindcss`.

`elsewise.css` holds values a theme overrides; `styles.css` holds structure no theme touches. Themes are color-only,
so `--radius` lives in `styles.css`. A new token gets its value in `elsewise.css`, light and dark, and its utility
mapping in `styles.css`. Reach for a token over a raw value.

## Adding a component

Run the shadcn CLI from this folder; preview with `--dry-run` first.

```sh
pnpm dlx shadcn@4.21.0 add <name>
```

After each `add`:

1. Rewrite `@elsewise/components/lib/utils` to `../lib/utils`, and `@elsewise/components/components/<x>` to `./<x>`.
2. Replace `import * as React` and every `React.X` with named imports.
3. Replace each Phosphor icon with `<Icon name="…" />`.
4. Review its edits to `src/styles.css`, and move values it added to `elsewise.css`.
5. Add the component to `exports` in `package.json`.
6. `pnpm --filter @elsewise/components check --write`.

## Tests

| Script         | What runs                                           |
|----------------|-----------------------------------------------------|
| `test`         | `{src,test}/**/*.test.{ts,tsx}`, plain Node, no DOM |
| `test:browser` | `src/**/*.browser.test.{ts,tsx}`, headless Chromium |
| `test:visual`  | `test/visual/**`, headless Chromium                 |
| `test:all`     | everything                                          |

- Co-locate a test with its module. Geometry or computed styles need `*.browser.test.tsx`; pixels belong in
  `test/visual/`.
- A component that brings a new dependency adds it to `optimizeDeps.include` in `vitest.config.ts`, or the browser
  projects fail on a cold cache.

### Visual tests

Baselines are **byte-exact**, blessed on macOS, and committed. When one flakes, fix the environment, not the
comparator. Dependencies are **pinned exactly** so a version bump is reviewed against the baselines; `vitest`,
`@vitest/browser` and `@vitest/browser-playwright` share one version.

Scope a rebless to a file, **path before the flag** — `--update` swallows a path that follows it and reblesses
everything:

```sh
pnpm --filter @elsewise/components exec vitest run --project visual test/visual/<file> --update
```

New sheets follow `test/visual/button.test.tsx`:

- One image per theme, not per cell: a matrix inside `<Sheet theme>`, captured via `getByTestId('sheet')`.
- Two sheets per component: prop-reachable states in one; `:hover`, `:focus-visible` and `:active` in another, forced
  via `forcePseudoStates`.
- Pad cells that paint outside their box, or the screenshot crops the focus ring.
- Call `settleTree(rows)` before shooting a tree, or the baseline captures blank icon lanes.
- Module-scope constants are `SCREAMING_CASE` with `as const`; tables inside a test body stay `camelCase`.
